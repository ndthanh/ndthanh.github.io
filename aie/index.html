Study notes · Neo4j TypeScript MCP course 14 lessons / 3 modules

A compact review of every lesson, followed by 20 new questions (31–50). These notes summarize the course examples; reading them does not run the exercises or mark challenges complete.

Module 1 · Getting Started with MCP

  1. 1.1 · Building MCP servers ↗

    McpServer registers three features: model-controlled tools, application-controlled resources, and user-controlled prompts. Zod validates inputs at runtime and supplies schema descriptions. The course uses stdio locally; Streamable HTTP is introduced for web deployment.

  2. 1.2 · Setting Up Your Development Environment ↗

    The starter repository can run in GitHub Codespaces or locally. Configure the Neo4j connection through environment variables, load them with dotenv, and run client/test_environment.ts to check configuration, connectivity, and a test query.

  3. 1.3 · Create Your First MCP Server ↗

    Build the countLetters tool with typed inputs, then connect the server to StdioServerTransport. The client starts the server as a child process. MCP Inspector lets you list capabilities and invoke the tool with test inputs; the example counts three occurrences of r in strawberry.

Module 2 · Building Database-Connected Features

  1. 2.1 · Connecting to Neo4j ↗

    Create the Neo4j driver once at module scope and reuse its connection pool across handlers. Select the target database through the executeQuery options. Close the driver and server during shutdown; creating and closing a driver for every call adds unnecessary overhead.

  2. 2.2 · Add Neo4j Connection ↗

    Wire neo4j-driver and dotenv into the server and implement graphStatistics to query graph counts. Keep connection credentials in an ignored .env file. Test the tool in MCP Inspector to confirm that the server can reach the configured database.

  3. 2.3 · Shared State and Logging ↗

    Handlers access module-scope variables through normal JavaScript closures. With stdio, reserve stdout for JSON-RPC and log to stderr using console.error. Return a content array for tool results; when a tool fails, use isError: true with a useful error message.

  4. 2.4 · Build a GraphRAG Tool ↗

    getMoviesByGenre accepts a genre and a result limit, traverses Movie–IN_GENRE–Genre, and returns movie facts as JSON text in a content block. Bind query parameters separately from Cypher text and pass the LIMIT value as neo4j.int(limit). These retrieved facts provide grounding for the agent.

  5. 2.5 · Using Resources ↗

    Resources expose read-only context through URIs. A static URI can publish a genre catalog; ResourceTemplate supports a pattern such as movie://{tmdbId}. The handler receives the parsed URI and extracted parameters. Setting list: undefined omits the resource-enumeration callback.

  6. 2.6 · Create a Movie Resource ↗

    Implement a movie resource keyed by TMDB ID. One graph query retrieves metadata, genres, directors, and a bounded cast list. Return contents with uri, mimeType, and serialized text. Handle missing movies and query failures explicitly, and test several IDs in the Inspector.

  7. 2.7 · Handling Large Datasets with Pagination ↗

    Return bounded pages instead of loading every record. In this example, the cursor is a string representation of an offset used with SKIP and LIMIT. Use consistent ordering, reasonable page sizes, and pagination metadata. A full page signals that more results may exist, not that another nonempty page is guaranteed.

  8. 2.8 · Build a Paginated Tool ↗

    browseMoviesByGenre combines the genre filter with cursor and pageSize. Results are ordered by rating descending and title ascending. A full page produces String(skip + pageSize); otherwise nextCursor is null. The response includes movies, page, pageSize, count, and hasMore. Test consecutive pages using the returned cursor.

  9. 2.9 · Building Prompts ↗

    registerPrompt returns reusable messages selected by the user. Define parameters with argsSchema; the lesson uses strings, including a string for a recommendation count. Templates can return multiple user and assistant messages. Clear steps and output structure guide later tool use without executing the tools themselves.

Module 3 · Integration and Advanced Features

  1. 3.1 · Integrated Workflows ↗

    Connect the stdio server to an AI editor by configuring the command that launches it. Build new tools through a verified sequence: inspect the graph schema, generate and test a parameterized Cypher query, then implement the tool. Domain instructions can document this workflow for the coding agent.

  2. 3.2 · Advanced MCP Features ↗

    Sampling lets a server request model assistance through the client, illustrated with mcp.server.createMessage; it requires client support and adds overhead. Completions suggest valid argument values, such as genre names matching a prefix. The lesson demonstrates a CompleteRequestSchema handler on the low-level server API.

Pagination detail: the example’s cursor encodes an offset for SKIP/LIMIT. Its hasMore flag is inferred from a full page; it is not a count of verified remaining rows.
